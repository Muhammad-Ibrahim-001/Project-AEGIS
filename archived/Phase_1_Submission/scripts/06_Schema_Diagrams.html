1. Multi-Tier Modeling Architecture Overview

In strict alignment with the course syllabus and Lab 3 (Logical vs. Physical Modeling), dimensional engineering requires a disciplined three-tier architectural progression:

  1. Conceptual Data Model: Defines high-level business entities, enterprise subject boundaries, and macroscopic relationships independent of database technology or technical attributes.
  2. Logical Dimensional Model: Establishes the formal Kimball Star Schema structure, defining business keys, conformed dimensions, multi-grain fact archetypes, attribute hierarchies, outrigger links, and Slowly Changing Dimension (SCD Type 2) tracking rules.
  3. Physical Data Model: Specifies target cloud lakehouse storage contracts on Delta Lake, precise ANSI SQL data types, surrogate identity keys, foreign key constraints, explicit grain statements, and Delta Liquid Clustering keys (CLUSTER BY).

3. Tier 2: Logical Dimensional Model (Kimball Star Schema)

The Logical Model transforms conceptual entities into a Kimball Star Schema with conformed dimensions and three multi-grain fact archetypes:

Figure 2: Logical Dimensional Model — Kimball Star Schema with Conformed Dimensions, SCD Type 2 Outrigger, and Multi-Grain Facts

Kimball Bus Design: DIM_DATE is conformed across all three facts. DIM_PLANT is conformed across the two facility-level facts. DIM_GENERATOR tracks asset status changes (OP → RE) via SCD Type 2. DIM_BALANCING_AUTHORITY connects plant-level emissions to regional grid demand via drill-across.
